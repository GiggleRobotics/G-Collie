# 2026-10-26 频繁“连接中”排查

## 反馈与范围

用户反馈手机经常显示“连接中”，怀疑与电脑连接断开。通过 USB 对已连接的 23127PN0CC 检查服务、日志和真机诊断；未重启服务、修改网络配置、重新登录或发送消息。

## 已取得的证据

- 手机安装版本为 0.1.10，versionCode 2012，最后更新时间 2026-10-26 01:16:50（手机报告）。App 进程存在。
- 电脑 g-collie.service 从 2026-10-26 00:36:28 起运行，NRestarts=0；内置网络子进程同次启动，检查时仍运行。不能据此排除网络链路间歇异常。
- 本机 /healthz 返回 HTTP 200，单次耗时约 1.2 ms。只证明检查时本机服务可达。
- 北京时间 19:32:58，手机诊断请求成功返回：电脑服务正常、会话索引正常、Codex 连接异常；手机首页显示已连接。
- 实际运行数据目录的 diagnostic-events.json 只有两条北京时间 00:48:55、00:48:56 的 POST /api/schedules/:id HTTP 400，未见本次断连对应记录。服务仅保存已完成的 HTTP 错误响应，不记录所有成功请求或未到达服务的失败，不能据此认定网络从未断开。
- 电脑日志在 18:12、18:29、19:02 等时刻出现 Codex 额度请求 401 token_revoked，属于上游登录凭据失效；尚无证据证明它导致手机到电脑断开。诊断页把该查询失败概括为“助手后端未响应”，描述不够准确。
- 手机当前进程 logcat 未取得可解释本次问题的应用日志。App 为非 debuggable 安装，run-as 不能读取私有数据；真机诊断页未显示“手机请求失败记录”，无法据此判断历史记录为空还是版本/读取路径差异。

## 源码发现与推断

- flutter_client/lib/main.dart 的 didChangeAppLifecycleState 在所有非 resumed 状态直接设置 online=false，没有先确认网络不可达。切后台、锁屏等可造成连接状态变化；是否对应用户每次遇到的现象尚未复现。
- failure() 将非 4xx 的请求错误统一标为 online=false，会话读取失败、超时或服务端错误也会表现为电脑未连接。因此该文案不是实际断网的充分证据。
- load() 在 online=false 时先走内置网络连接及授权检查，再读取会话列表；会话列表成功后才恢复在线。状态误判可能放大用户感知的重连过程，具体耗时尚未测量。

## 结论与剩余工作

检查当时手机到电脑服务可达，未发现电脑服务重启；已确认 Codex 额度凭据异常，并发现连接状态判定过于宽泛。频繁“连接中”的实际根因尚未确认，不能把网络波动、Codex 凭据或生命周期逻辑中的任一项直接认定为唯一原因。
