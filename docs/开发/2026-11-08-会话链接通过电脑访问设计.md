# 会话链接通过电脑访问：Bug 5 设计建议

日期：2026-11-08。状态：设计草案，尚未实现。

## 设置与范围

在手机「设置 → 网络与连接」增加开关「会话链接通过电脑访问」，默认关闭。

说明文案：「开启后，App 内打开的会话网页通过当前连接电脑访问，使用电脑可用的网络或代理。电脑需保持在线；手机仍会消耗流量。」

- 按已配对电脑分别保存偏好，切换电脑时使用对应配置。
- 覆盖 Codex、Hermes、Claude Code 会话里的 HTTP/HTTPS 网页，包括网页内后续跳转及子资源。
- 首期限定会话内浏览页面；手机其他应用、系统浏览器、配对授权页面和应用升级不纳入此开关。
- 本地附件继续使用现有会话资源读取方式。下载若尚未支持同一路由，明确提示，不自动改用手机直连。

## 使用流程

1. 开启时检查当前电脑连接及转发能力，显示检测结果；失败允许保留开启偏好，页面提示等待电脑恢复。
2. 点击会话链接进入现有 App 内网页，顶部显示网站域名和「通过电脑 · 电脑名称」；直连模式显示「手机网络」。
3. 电脑断连或电脑侧访问失败，留在网页内显示具体失败阶段，提供「重试」和「本次使用手机网络」。不静默回退，避免用户误以为仍在走电脑。
4. 单次改用手机网络不修改全局偏好。设置开关变更后，下次打开页面生效；当前页面提示重新加载以应用，避免打断表单填写。
5. 网页返回先回退网页历史，再回到原会话，保留会话滚动位置和草稿。

设置预览文案：

> 会话链接通过电脑访问　[开关]
>
> 使用当前电脑的网络打开会话网页
>
> 当前电脑：DEVELOPMENT_COMPUTER
>
> 连接检测：可用／电脑离线／电脑无法访问目标网站

## 实现方向及待验证点

现有手机网页入口为 `flutter_client/lib/session_web.dart`，使用 `webview_flutter`；已有内置私有网络连接能力。建议沿现有配对连接增加受鉴权的电脑转发通道，让手机会话 WebView 的请求经通道到电脑，再由电脑访问目标站点。

优先验证原生 WebView 代理与 HTTPS CONNECT 隧道方案，保持原站 URL、HTTPS 校验及站点 Cookie 行为。手机本地转发入口只监听回环地址，通过既有受保护连接访问电脑转发服务；电脑出口需要显式使用可用的系统路由或代理配置。电脑浏览器能访问不代表后台服务已继承同样的 VPN／代理，需单独检测并给出配置提示。

不以服务端抓取 HTML 并改写链接作为正式浏览方案：页面脚本、登录、重定向、跨域请求和视频资源均需要完整请求路径支持。原生代理能力、WebSocket、DNS 出口、媒体与下载兼容需要原型验证后确定，暂不承诺所有网站可用。

WebView 代理若作用于整个应用进程，需隔离会话浏览与配对授权等页面，或限制相关页面并发，避免开关影响其他 WebView。代理建立与失败期间也应阻止意外直连。

转发服务沿用配对设备权限，仅授权设备可用；连接凭据不放入网站 URL 或转发给目标网站。首期仅支持公网 HTTP/HTTPS，拒绝本机、私网及云元数据地址，并处理重定向与 DNS 解析后的地址检查。电脑 localhost／内网站点访问作为独立需求后续设计。HTTPS 使用隧道转发，不安装解密证书，也不继承电脑浏览器登录态。

## 验收条件

- 手机直连失败、电脑可访问的真实链接，开启后能在 App 内完整打开；电脑后台无法访问时准确提示。
- 主页面、图片、脚本、重定向、站内链接均通过电脑；电脑侧解析目标域名，检查没有手机直连泄漏。
- 开关关闭后恢复手机访问；两台电脑的偏好互不影响。
- 断连、切网、电脑休眠后失败可见，重试可恢复，单次直连需要用户主动选择。
- 登录 Cookie 与会话返回行为正常，HTTPS 证书检查保留，未授权设备无法使用转发服务。
- 验证 WebView 代理作用域、下载、视频及 WebSocket；未支持能力在界面明确说明。
