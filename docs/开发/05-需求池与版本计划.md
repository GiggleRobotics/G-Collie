### FILE-01：App 内查看下载内容与下载记录

- 提出日期 / 来源：2026-10-25，用户反馈下载后需要能直接查看内容，不能仅提示到系统下载记录中查找。
- 目标与预期：下载完成后提供“打开”入口，在 App 内可找到已下载内容并直接查看；已下载文件使用手机本地副本，电脑离线时仍可打开。
- 建议交互：下载开始显示进度或状态，完成后提示“下载完成”并提供“打开”；设置或侧栏提供统一“下载内容”入口，展示文件名、类型、下载时间、大小和状态，点击成功记录打开文件。入口位置在原型评审时确定。
- 查看方式：图片沿用支持缩放的查看器；可支持的文档使用本地预览；其他格式提供“使用其他应用打开”。文件不存在或无法打开时说明原因，并在来源电脑在线时提供重新下载入口。
- 实现关注：当前原生下载仅确认系统任务已入队，需跟踪实际完成/失败结果，保存可访问的本地文件 URI 与下载记录，区分下载中、成功与失败，不把“开始下载”当作“下载成功”；支持系统下载存储权限和安全文件分享机制。
- 建议验收条件：从会话链接与查看页下载的文件均可在完成后直接打开；下载内容列表重启后保留，成功文件在电脑断开时仍可查看；失败任务明确显示原因并可重试；外部删除文件后有明确提示，未知格式可交给其他应用打开。
- 状态：已记录；待原型评审和排期，尚未开发。是否增加删除记录、删除本地文件及批量管理另行确定。

### BUG-02：额度重置按钮疑似禁用但仍显示绿色，缺少原因说明

- 提出日期 / 来源：2026-10-25，用户提供深色主题用量页截图，并补充按钮似乎无法点击。
- 现象：页面显示已连接、重置卡“可用 2 次”，两个“重置额度”按钮呈浅绿色，文字对比度低，用户反馈疑似不可点击。
- 代码分析：`flutter_client/lib/reset_credits.dart` 紧凑按钮使用 `OutlinedButton.styleFrom` 显式指定主题主色背景，但未单独定义禁用背景与文字颜色；禁用时仍可能保留绿色背景，搭配默认禁用文字后难以辨认。深色主题主色由 `ColorScheme.fromSeed` 生成，可呈浅绿色。
- 禁用条件：初始化记录尚未恢复、正在提交、只读设备、缺少 `accountKey`、缺少重置卡汇总，或无可用次数且无待确认操作。可用次数不为零并不代表其他条件满足；截图无法确认具体触发项，尚未复现当时状态。
- 建议修复：明确区分可操作、加载、提交和不可操作样式；禁用背景与文字需有清晰对比，并展示具体原因。初始化或存储读取失败应有恢复入口；核查已连接且有可用卡时是否因账号字段或权限状态异常而持续禁用。
- 建议验收条件：有权限、账号信息齐全且初始化成功时可点击并进入确认；各种禁用条件均有可见说明；深浅主题文字清晰；“可用次数”与按钮状态的关系可理解，不让用户误认为卡片无效。
- 真机联查（2026-10-25）：手机已通过 ADB 连接，当前为 G-Collie 用量页；读取运行中电脑服务 `GET /api/usage/limits` 返回 200、`limitsError: null`、两张卡 `status: available`，但 `accountKey` 为空。该字段为空会直接触发 Flutter 按钮禁用，确认至少存在此项阻断，不能归因于卡片次数不足。后续需排查账号标识提取与实际上游账号结构的兼容性。
- 进一步核查：使用当前源码的 `CodexBridge.usageLimits()` 直接只读查询 Codex 后端，确认能取得非空 `accountKey`、`accountId` 与账号标签；运行中服务强制刷新 `/api/usage/limits?refresh=1` 后仍返回空 `accountKey`、两张可用卡。因此不能认定账号本身缺少标识或卡片不可用。
- 原因定位范围：运行中服务通过 `codex.usageLimits().catch(() => desktopCreator.usageLimits())` 获取额度；回退的桌面 `get_usage_limits` 查询没有补齐本项目需要的账号标识，汇总层会将缺失值变为 null，最终触发手机按钮禁用。当前证据指向直接查询失败后的回退链路或运行中后端状态；尚未捕获该进程原始查询异常，具体失败原因待排查，不应将回退触发原因视为已确认。
- 修复约束：修复账号读取与回退数据兼容，保留重置前账号一致性检查，不以删除 `accountKey` 校验或强行启用按钮代替修复；本次排查未消费重置卡。
- 修复与验证（2026-10-25）：额度响应已有 `accountId` 时直接用于账号一致性校验，不再依赖额外 `account/read`；没有 ID 时才读取邮箱，身份仍缺失则明确报错。只读额度查询失败重试一次，回退时保留不可重置原因及服务日志；手机补充灰色禁用样式和原因说明。更新运行中服务后强制查询得到非空账号标识、2 张可用卡、无不可用原因。后端账号与重置回归通过，新增 Flutter 测试验证缺少标识时禁用并提示、标识恢复后可进入确认且不消费卡。
- 状态：修复已更新到当前电脑服务及连接手机（覆盖安装成功）；用户将自行验证重置按钮，保留待验收。未实际消费重置卡，上游原始异常未能追溯。

### BUG-01：Codex 会话图片无法内联显示、预览和下载

- 提出日期 / 来源：2026-10-25，用户提供两张手机截图，要求记录并分析原因。
- 影响会话：`查看 ZZ 程序启动方式`，会话 ID `01a168f7-4da6-7c73-ab40-77daf13f7268`。
- 现象：会话内图片退化为“点击打开或重试”按钮；进入图片查看页后提示“图片加载失败，请返回重试”；下载也失败。截图中的会话页同时显示“连接中 / 等待电脑连接”，连接状态可能叠加影响，但不能仅据此归因于网络。
- 文件与消息核查：原会话在北京时间 19:10 与 19:12 引用同一文件 `/home/giggle/.codex/visualizations/2026/10/23/01a168f7-4da6-7c73-ab40-77daf13f7268/zz-pc-desktop-20261025.png`；文件目前存在，大小为 1,638,901 字节，未超过服务端 50 MB 或 Flutter 图片 15 MB 限制，Markdown 图片与下载链接路径一致。
- 已复现的代码原因：`server/resources.ts` 的 `resourceFile` 明确允许 `.codex`、`.hermes` 隐藏目录，但 `server/index.ts` 图片资源接口和 `server/resources.ts` 预览内容/下载接口均使用未指定 `dotfiles` 的 `res.sendFile`。Express 默认忽略隐藏路径，导致前面的业务校验通过后，发送文件阶段仍返回 404。预览票据可成功签发，因此能进入图片查看页，但实际图片与下载内容读取失败。
- 验证证据：使用当前项目 Express 依赖及上述原始 PNG 启动临时本地接口，默认 `sendFile(path)` 返回 `404 text/html`；相同文件使用 `sendFile(path, {dotfiles: 'allow'})` 返回 `200 image/png`，内容长度 1,638,901 字节。已确认该机制足以造成三处失败；尚未抓取手机当时请求，不能排除连接问题叠加。
- 建议修复方向：仅对已经过会话引用、文件类型、大小及敏感路径校验的文件发送显式允许隐藏目录；统一检查图片、预览和下载出口，保留现有安全校验。补充隐藏目录资源的接口回归验证，并改善加载错误信息，区分连接失败、文件不存在与访问受限。
- 建议验收条件：本会话原图能内联显示、点击放大与下载；普通目录和允许的隐藏目录资源均正常；未被会话引用的文件及凭据等敏感文件仍不可访问；断线、文件删除和票据过期有明确提示。
- 修复与验证（2026-10-25）：在已有会话引用与敏感路径校验之后，图片和预览/下载发送接口显式允许隐藏目录。回归验证允许的 `.codex` 图片可读、敏感文件仍被拒绝。更新当前电脑服务后，原会话图片接口及预览票据下载均返回 200，内容长度均为 1,638,901 字节。
- 缩放问题补充（2026-10-25）：用户反馈首次点击无法放大、点击下载后可缩放但仍局限于一小块。代码确认 `Center → InteractiveViewer → Image` 令缩放视口随图片高度收缩，宽图放大仍被窄区域裁剪，且原实现未提供双击放大。已将视口与图片布局框扩展为标题栏下完整区域，保留双指缩放/拖动，新增双击 3 倍放大与再次双击复位，并显式持有变换控制器，避免下载状态重建影响缩放状态。下载后才可缩放的具体手势时序尚未真机确认。
- 缩放验证：新增宽图组件测试，确认视口占满查看区域、空白区域双击可立即放大与复位，无需下载；Flutter 静态检查通过。修复 APK 已覆盖安装成功，后续真机操作途中 ADB 再次断开。

### OBS-01：故障诊断入口与运行、连接诊断日志

- 提出日期 / 来源：2026-10-24，用户反馈并要求记录。
- 用户场景与问题：2026-10-24 18:50–19:15（北京时间），手机使用 App 内置网络，期间没有切换 Wi-Fi，界面持续显示重连。电脑服务日志未见该时段重启记录，但缺少手机请求与内置网络日志，无法确定根因。不能据此认定为 Wi-Fi 切换、网络断线或服务端故障。
- 入口与原型（2026-10-25）：用户要求增加故障诊断入口；顶部电脑栏右上角三个点菜单新增“故障诊断”（用户确认），工作台菜单不重复展示，展示手机网络、电脑连接、电脑服务、助手连接及文件访问的分项结果，可展开查看证据、原因与建议；支持重新检查、最近故障详情和导出说明。原型含连接/助手/文件异常及正常场景，均为模拟，不读取真实日志。无法确认时显示原因未确认，未检查不等于故障。
- 目标与预期：手机端和电脑端均保留可回溯的运行与连接日志，能够按用户反馈的时间段还原连接、请求、失败和恢复过程，区分网络不可达、内置网络异常、服务端接口失败与会话读取失败。
- 建议优先级：P1。
- 状态：已确认需记录；待排期，具体实现范围与日志保留策略待确认，尚未开发。
- 受影响页面 / 助手：连接与配对、工作台重连状态、连接诊断入口；三助手共用链路。
- 建议范围：
  - 手机运行：启动/退出可观察事件、前后台切换、客户端版本、连接方式，以及连接状态变化的时间与原因。
  - 内置网络：启动、登录状态恢复、通道建立、断开、重试次数与间隔、探测结果和恢复；电脑端同步记录网络进程退出与恢复，避免静默丢弃全部诊断信息。
  - 接口请求：时间、接口路径模板、请求关联 ID、耗时、状态码和错误分类；区分连接超时、响应超时、网络异常、鉴权失败及业务接口失败。两端使用同一请求 ID 关联记录。
  - 排障取证：日志落盘并按大小/时间轮转，支持按时间段查看或导出诊断包；记录时区、版本与启动实例，便于对齐两端时间。保留时长、容量上限及导出入口在实现前确定。
  - 隐私：不记录密钥、Cookie、配对码、登录链接、聊天正文和附件内容；错误信息与导出内容脱敏。
- 正常 / 异常流程：正常运行持续保留必要诊断事件；重连时记录首次失败、各次重试和最终恢复或失败原因；用户反馈时间段后可提取两端日志分析。
- 建议验收条件：
  1. 分别模拟网络不可达、内置网络启动失败、接口超时、服务端 5xx、会话读取失败，日志可区分失败层级，界面状态变化有对应原因。
  2. App 前后台切换、重启及电脑服务重启后，可读取保留范围内的历史日志；失败请求能够通过请求 ID 关联两端记录，未到达服务端的请求有手机端失败证据。
  3. 可提取指定时间段（例如本次 18:50–19:15）的诊断材料，包含重连次数、持续时间及恢复结果；无法确定原因时明确标记证据缺口。
  4. 验证日志轮转与容量限制有效，诊断包不包含上述敏感内容；持续重连不会导致日志无限增长。
- 关联代码：`flutter_client/lib/main.dart`、`flutter_client/lib/api.dart`、`flutter_client/lib/native.dart`、`server/embedded-network.ts`、`server/index.ts`、`network/core/core.go`。
