## 验收要求

用户明确要求与 App 页面一致，这是验收硬要求。禁止另行重画近似布局、替换文案或简化产品页面。浏览器与 Android 无法等价的能力不视为通过，必须回到同版本真机核验；未完成真机核验前状态为“待验收”。

## 如何保证一致

构建脚本从 `flutter_client/lib/` 复制生产页面，编译前逐字节比对；不修改 `main.dart`、`project_picker.dart`、`process_record.dart`、`resources.dart`、`preview.dart`、`reset_credits.dart`。素材与依赖清单也来自同一个 Flutter 项目。源码 SHA-256 清单见 [source-manifest.json](source-manifest.json)。

仅在隔离的构建目录替换 `api.dart`、`native.dart` 与原型专用 `ui.dart`，使用模拟数据和明确受限的原生能力适配；`preview_main.dart` 选择原始页面、真实 App 主题和起始状态。生产 Flutter 源码不受影响。

除原型专用 `ui.dart` 外，一致性保证是“页面组件源码相同”，不是“已确认与任意已安装 APK 像素完全相同”。Android 与浏览器可能有字体、文本缩放、系统返回和渲染差异；当前无连接的 Android 设备，尚未对手机已安装包逐页截图比对。安装包可能早于仓库当前源码，不能把两者直接视为相同版本。

## 原生能力与数据边界

原型不发送网络请求给电脑或 Agent，不读取真实会话、账户和配对凭证，不修改实际项目目录或消费卡片。演示配对可能由原始 Flutter 安全存储插件在当前浏览器中保存演示地址，不是手机授权。

Android 的网络授权、通知、系统文件选择、视频上传/抽帧、WebView 文档阅读和下载不能在浏览器等价呈现。这些入口保留生产组件，未实现的适配明确报错或保持未提供状态，不另外画一个看似可用的替代流程。完整行为必须在 Android 真机验收。模拟用量和会话不是完整后端实现，也不能用于验证账务、协议或并发正确性。
