## 源码定位

1. server/usage.ts 的 accountRead 并行等待额度与账号 Token 统计，两者全部完成后才返回；其中额度失败被转为空 limits + limitsError，外层仍可返回 HTTP 200。刷新受 60 秒缓存影响；查询失败结果同样缓存。
2. flutter_client/lib/quota_notice.dart 的 build 在未判定耗尽且无显式额度错误时直接隐藏卡片。load 不处理响应内 limitsError，查询失败可能变成静默隐藏。仅识别 300/10080 分钟窗口；其他窗口不会显示。需验证实际失败时的响应，不能把窗口筛选当作已证实根因。
3. server/index.ts 发送时仅在错误包含“桌面执行状态尚未同步”时补查额度，其余 409 不做额度识别；错误分类不完整。
4. server/index.ts 诊断在 UsageService 已丢弃原始异常后再用正则检测 401，因而难以准确呈现凭证失效。
5. flutter_client/lib/api.dart 把非 ApiException 异常统一归为 transport-timeout，日志欠缺业务错误码、异常类型和失败耗时。server/diagnostic-store.ts 标识校验不接受查询字符串，部分路由在上传后成为 unknown，妨碍定位。
6. 会话链接在 resources.dart 使用 externalApplication，确认会跳外部浏览器。文件预览已有 WebView，但导航限制针对受控文件，正式实现网页浏览应单独提供页面。
7. 重置 UI 当前直接显示完整 DateTime（含秒/小数）及较长卡片描述，紧凑提示和完整用量页的视觉层级需统一。不能仅凭代码断言手机出现溢出，仍待同版本截图核对。

“用量统计那里也收不到消息”暂按账号额度/Token 数据不能更新分析；若指系统通知或会话消息，当前证据不足，需要单独核对具体入口。

## 原型评审点

- 额度耗尽：保留双窗口、用量统计与重置入口；重置使用情况在同一演示会话共享。
- 查询失败：显式提示“暂时无法确认”，隐藏模拟正常额度，不显示 0% 或健康进度；禁止在额度未确认时消耗重置卡。
- 登录失效：电脑连接保持独立状态，提示到电脑重新登录，再检查。
- Codex 超时：保留草稿、提供重新检查，不自动重复发送。
- 重置确认：包含账号、范围、卡片到期时间和使用前后次数；修正已经过期的演示日期，重置次数徽标使用主题灰阶。
- 会话网页：App 内独立页面、域名标题、返回会话、复制链接。浏览器原型只展示说明占位，不请求外站；正式 WebView 及系统返回仍须真机实现与验收。

## 后续正式实现建议

先定义额度与助手连接错误码、分离额度和 Token 查询、保留最后有效额度及时间、进入会话/恢复前台主动刷新，再统一会话与用量页状态。完善诊断日志后复现桌面 409 和响应丢失；不能用原型模拟成功作为真机连接修复证据。
